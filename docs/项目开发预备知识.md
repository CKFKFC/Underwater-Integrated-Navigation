# GitHub + VS Code + MATLAB 协作开发新手教程

本文面向第一次或不熟悉 GitHub 协作、VS Code 开发 MATLAB 的项目成员。目标是让每位成员都能完成三件事：

1. 正确加入 GitHub 组织和项目仓库。
2. 在本机配置 Git、VS Code、MATLAB 开发环境。
3. 按统一流程开发、提交代码、发起合并请求，避免互相覆盖代码。

本文默认项目组织为：

- GitHub 组织：<https://github.com/UnderWater-Swarm>
- 项目仓库：由负责人在该组织下新建，命名为: `Underwater-CL-2026`

如果你是普通成员，建议按顺序阅读第 2 至 9 节。如果你是项目负责人或仓库管理员，请先阅读第 1 节。

## 0. 先理解三个概念

### GitHub 是什么

GitHub 是远程代码仓库。大家把代码上传到同一个仓库，GitHub 负责保存历史记录、显示每次改动、帮助大家审查和合并代码。

### Git 是什么

Git 是本地版本管理工具。它安装在每个人电脑上，用来记录你的代码改动，并把改动推送到 GitHub。

### VS Code 是什么

VS Code 是代码编辑器。我们用 VS Code 写 MATLAB 代码、查看 Git 改动、提交 commit、解决冲突。MATLAB 本体仍然用于运行 `.m` 文件、调试算法、画图和验证结果。

可以简单理解为：

- GitHub：团队共享代码的位置。
- Git：本地和 GitHub 之间同步代码的工具。
- VS Code：平时写代码和操作 Git 的图形界面。
- MATLAB：运行和验证惯性基协同导航算法的环境。

## 1. 项目负责人先做的事

本节由组织管理员或仓库负责人执行。

### 1.1 在组织中新建仓库

进入 <https://github.com/UnderWater-Swarm>，点击 `Repositories` -> `New repository`。

建议设置：

- Owner：`UnderWater-Swarm`
- Repository name：建议使用英文和连字符，例如 `Underwater-CL-2026`
- Visibility：如果项目暂不公开，选择 `Private`
- README：可以勾选，也可以后续自己创建
- `.gitignore`：选择 `MATLAB`
- License：如果项目暂不对外发布，可以先不选；如果后续开源，再统一讨论许可证

仓库建好后，复制仓库地址。推荐使用 HTTPS 地址：

```text
https://github.com/UnderWater-Swarm/仓库名.git
```

### 1.2 邀请还没加入组织的成员

进入 GitHub 组织页面：

```text
https://github.com/orgs/UnderWater-Swarm/people
```

点击 `Invite member`，输入成员的 GitHub 用户名或邮箱，发送邀请。

注意：

- 成员必须接受邮件或 GitHub 通知中的邀请，才算真正加入组织。
- 如果成员没有 GitHub 账号，需要先注册账号。
- 负责人应确认所有成员都能看到组织和项目仓库。

### 1.3 设置成员权限

建议新手成员先使用 `Write` 权限，不直接给 `Admin` 权限。

推荐权限：

- 负责人 / 维护者：`Admin` 或 `Maintain`
- 普通开发成员：`Write`
- 只看代码、不提交代码的成员：`Read`

如果后续人数更多，建议在组织里建立 Team，例如：

- `navigation-core`：核心算法开发
- `simulation`：仿真和测试
- `docs`：文档和实验记录

### 1.4 保护 main 分支

建议不要让所有人直接把代码推送到 `main` 分支。推荐流程是：

```text
个人分支 -> Pull Request -> 至少一人检查 -> 合并到 main
```

仓库管理员可进入：

```text
Settings -> Branches -> Branch protection rules -> Add rule
```

建议设置：

- Branch name pattern：`main`
- 勾选 `Require a pull request before merging`
- 勾选 `Require approvals`，建议至少 1 人批准
- 勾选 `Require conversation resolution before merging`
- 新手阶段可以暂时不强制 CI，等项目有自动测试后再开启

这样可以减少误删、误覆盖、未验证代码直接进入主线的问题。

## 2. 每位成员需要安装的软件

### 2.1 安装 Git

下载并安装 Git for Windows：

```text
https://git-scm.com/downloads/win
```

安装时大多数选项保持默认即可。建议确认以下选项：

- 默认编辑器可以选 VS Code。
- PATH 相关选项保持默认推荐值。
- 换行符选项使用 Windows 默认推荐即可。

安装完成后，打开 PowerShell，输入：

```powershell
git --version
```

如果能看到版本号，说明安装成功。

### 2.2 配置 Git 用户信息

每个人只需要配置一次。打开 PowerShell：

```powershell
git config --global user.name "你的英文名或GitHub用户名"
git config --global user.email "你的GitHub邮箱"
```

查看配置：

```powershell
git config --global --list
```

注意：这里的邮箱建议和 GitHub 账号邮箱一致，否则 GitHub 可能无法正确关联你的提交记录。

### 2.3 安装 VS Code

下载并安装 VS Code：

```text
https://code.visualstudio.com/
```

安装时建议勾选：

- Add to PATH
- Open with Code
- Register Code as an editor for supported file types

### 2.4 安装 MATLAB

安装课题组统一使用的 MATLAB 版本。建议项目组明确写在 README 中，例如：

```text
MATLAB R2021b及以上版本
```

尽量所有成员使用相同或相近版本，避免函数、工具箱、仿真行为不一致。

建议负责人在 README 中维护以下信息：

- 推荐 MATLAB 版本
- 必需工具箱，例如 Navigation Toolbox、Sensor Fusion and Tracking Toolbox、Signal Processing Toolbox 等
- 是否需要 Simulink
- 是否需要自定义数据集或大文件

### 2.5 安装 VS Code 插件

打开 VS Code，进入 Extensions，搜索并安装下面这些插件。它们不是必须安装，但建议新成员统一安装，后续协作和排查问题会更方便。

推荐安装：

1. `Chinese (Simplified) (简体中文) Language Pack for Visual Studio Code`：把 VS Code 界面切换为简体中文，适合刚开始使用 VS Code 的成员。
2. `MATLAB`，发布者为 `MathWorks`：用于 `.m` 文件语法高亮、代码分析、代码片段等。
3. `Git Extension Pack`：集成多种 Git 辅助工具，方便查看提交历史、分支和文件改动。具体包含内容以插件页面为准。
4. `GitHub Pull Requests`：可以在 VS Code 中查看 Pull Request、评论和代码审查信息。
5. `Todo Tree`：可以把代码中的 `TODO`、`FIXME` 等标记集中显示，方便跟踪待办事项。

可选增强：

- `EditorConfig for VS Code`：配合 `.editorconfig` 文件统一缩进、换行符、文件编码等编辑器行为。等项目后续增加 `.editorconfig` 后更有用。
- `Markdown All in One`：写 README、实验说明、会议记录等 Markdown 文档时更方便。

其中 MATLAB 插件主要改善 VS Code 中的编辑体验。具体运行和调试仍建议使用 MATLAB 本体完成，尤其是涉及绘图、路径、工具箱和复杂调试时。

## 3. 第一次获取项目代码

### 3.1 选择本地存放位置

建议在本机选择一个固定目录，例如：

```text
D:\Projects
```

不要把仓库放在微信、QQ、OneDrive 自动同步目录里，容易产生重复文件或冲突。

### 3.2 克隆仓库

打开 VS Code，按 `Ctrl + Shift + P`，输入：

```text
Git: Clone
```

粘贴仓库地址：

```text
https://github.com/UnderWater-Swarm/仓库名.git
```

选择本地保存位置。克隆完成后，VS Code 会询问是否打开该仓库，选择打开。

也可以用命令行：

```powershell
cd D:\Projects
git clone https://github.com/UnderWater-Swarm/仓库名.git
cd 仓库名
code .
```

### 3.3 确认仓库连接正常

在 VS Code 终端中执行：

```powershell
git status
git remote -v
```

正常情况下你应该看到：

- 当前分支一般是 `main`
- 远程地址指向 `https://github.com/UnderWater-Swarm/仓库名.git`


## 4. 每天开发的标准流程

不要直接在 `main` 分支上开发。每次做一个任务，都新建自己的分支。

### 4.1 开始工作前先同步 main

在 VS Code 终端中：

```powershell
git switch main
git pull
```

这一步是把别人已经合并的最新代码拉到本地。

### 4.2 为本次任务新建分支

分支命名建议：

```text
类型/姓名-任务简述
```

例子：

```text
feature/zhangsan-ins-mechanization
fix/lisi-ekf-dimension
docs/wangwu-readme
experiment/zhaoliu-dvl-test
```

创建并切换分支：

```powershell
git switch -c feature/zhangsan-ins-mechanization
```

常见类型：

- `feature`：新增功能
- `fix`：修复问题
- `docs`：文档
- `test`：测试
- `experiment`：实验脚本
- `refactor`：重构

### 4.3 修改代码

在 VS Code 中编辑 `.m` 文件。建议遵守：

- 一个函数一个 `.m` 文件。
- 不要把本机绝对路径写死在代码里，例如 `C:\Users\xxx\Desktop\data.mat`。
- 不要提交临时测试脚本，例如 `test1.m`、`newnew.m`、`最终版.m`。

如果需要读取数据，建议使用相对路径或统一配置文件。

### 4.4 在 MATLAB 中运行验证

打开 MATLAB，把仓库根目录设为 Current Folder。

建议每次运行前执行：

```matlab
restoredefaultpath;
addpath(genpath(pwd));
```

如果项目后续使用 MATLAB Project，则以 `.prj` 文件为准，由 MATLAB Project 统一管理路径。

开发完成后，至少运行：

- 你改动相关的脚本。
- 你改动相关的测试。
- 一个最小 demo，确认没有破坏主流程。

### 4.5 查看自己改了什么

在 VS Code 左侧 Source Control 面板可以看到所有改动。

也可以用命令：

```powershell
git status
git diff
```

提交前请检查：

- 有没有误提交 `.mat`、`.fig`、大图片、大日志。
- 有没有误提交本机路径、个人临时文件。
- 代码是否能在别人电脑上运行。
- 注释是否说明了关键算法、坐标系、单位、输入输出。

### 4.6 提交 commit

先添加文件：

```powershell
git add 文件名
```

如果确定所有改动都要提交：

```powershell
git add .
```

提交：

```powershell
git commit -m "实现惯导解算基础函数"
```

提交信息建议写清楚做了什么，不要写：

```text
update
fix
修改
最终版
```

推荐格式：

```text
实现XXX
修复XXX
补充XXX说明
重构XXX模块
```

### 4.7 推送到 GitHub

第一次推送新分支：

```powershell
git push -u origin feature/zhangsan-ins-mechanization
```

之后同一个分支继续推送：

```powershell
git push
```

### 4.8 发起 Pull Request

推送后，打开 GitHub 仓库页面，通常会看到 `Compare & pull request` 按钮。

创建 Pull Request 时填写：

- 标题：一句话说明这次改动。
- 内容：说明做了什么、如何测试、是否有需要别人重点看的地方。

建议模板：

```markdown
## 本次改动
- 

## 测试情况
- [ ] 已运行相关 MATLAB 脚本
- [ ] 已运行相关测试
- [ ] 已确认没有提交大文件或临时文件

## 需要重点检查
- 
```

发起 Pull Request 后，至少请一位同学检查。检查通过后再合并到 `main`。

## 5. 如何处理常见问题

### 5.1 忘记先 pull，推送失败

先切回自己的分支，然后拉取远程变化：

```powershell
git pull
```

如果提示有冲突，不要慌，先看第 5.2 节。

### 5.2 出现冲突怎么办

冲突通常是两个人改了同一个文件的同一部分。

VS Code 会在冲突文件中显示类似：

```text
<<<<<<< HEAD
你的版本
=======
别人的版本
>>>>>>> 分支名
```

处理方法：

1. 打开冲突文件。
2. 判断应该保留哪一段，或把两边内容合并。
3. 删除 `<<<<<<<`、`=======`、`>>>>>>>` 这些标记。
4. 保存文件。
5. 运行 MATLAB 验证。
6. 重新提交：

```powershell
git add 冲突文件
git commit
git push
```

如果不确定怎么合并，不要随便删除别人的代码，先在群里问对应作者。

### 5.3 不小心在 main 上改了代码

如果还没提交，可以把当前改动暂存起来：

```powershell
git stash
git switch -c feature/你的名字-任务
git stash pop
```

然后继续正常提交。

### 5.4 提交了不该提交的大文件

如果只是本地 commit 了，还没 push，先找负责人或熟悉 Git 的同学处理。

如果已经 push 到 GitHub，不要继续反复提交更多修复 commit。大文件可能已经进入历史记录，需要专门清理。

以后注意：

- `.mat`、`.fig`、大型 `.csv`、大型 `.xlsx`、仿真结果文件默认不要提交。
- 数据说明可以写进 `data/README.md`。
- 结果说明可以写进 `results/README.md`。

### 5.5 MATLAB 找不到函数

常见原因：

- 当前 MATLAB 工作目录不是仓库根目录。
- 没有把 `src/` 加入路径。
- 文件名和函数名不一致。
- 函数放在了错误目录。

可以先在 MATLAB 中执行：

```matlab
pwd
which 函数名 -all
```

确认当前路径和函数位置。

## 6. MATLAB 代码协作规范

### 6.1 函数文件建议格式

```matlab
function navState = updateNavigationState(navState, imuSample, config)
%UPDATENAVIGATIONSTATE Update navigation state using one IMU sample.
%
% Inputs:
%   navState  - Navigation state structure.
%   imuSample - One IMU sample, including gyro and accelerometer data.
%   config    - Algorithm configuration.
%
% Outputs:
%   navState  - Updated navigation state structure.

arguments
    navState struct
    imuSample struct
    config struct
end

% Implementation here.
end
```

建议说明：

- 输入输出含义。
- 单位，例如 `rad/s`、`m/s^2`、`m`。
- 坐标系，例如 body frame、navigation frame、ECEF、NED。
- 时间戳单位和采样频率。

### 6.2 命名建议

建议使用英文命名：

- 函数名：`lowerCamelCase`，例如 `updateKalmanFilter`
- 变量名：`lowerCamelCase`，例如 `imuSample`
- 常量或配置字段：语义清楚，例如 `config.gravity`
- 脚本名：动词开头，例如 `runCooperativeNavigationDemo.m`

避免：

- `a1`、`temp2`、`newdata`
- `程序1.m`
- `最终版_真的最终.m`
- 拼音和英文混用

### 6.3 坐标系和单位必须写清楚

惯性导航代码最容易出错的是坐标系、单位和时间同步。以下内容必须在代码或文档中说明：

- IMU 角速度单位是 `deg/s` 还是 `rad/s`
- 加速度是否已经去除重力
- 姿态表示是欧拉角、四元数还是方向余弦矩阵
- 位置坐标是经纬高、NED、ENU 还是 ECEF
- 时间戳单位是秒、毫秒还是采样点编号
- 协同导航中各节点的编号、通信时延和观测定义

### 6.4 脚本不要承担太多核心逻辑

脚本适合做实验流程，例如：

```matlab
load data
set config
call function
plot result
```

核心算法应尽量放在函数中。这样更容易测试、复用和审查。

## 8. 团队协作约定

建议项目组明确以下约定，并写在 README 中。

### 8.1 不直接推送 main

所有功能改动都通过 Pull Request 合并。

### 8.2 小步提交

一次 PR 尽量只做一件事，例如：

- 实现一个滤波函数
- 修复一个维度错误
- 补充一个实验脚本
- 更新一段说明文档

不要把几周的所有修改一次性提交。

### 8.3 提交前自查

每次发 PR 前确认：

- 代码能运行。
- 没有提交临时文件。
- 没有提交大数据和大结果文件。
- 关键算法有注释。
- 修改内容和 PR 标题一致。

### 8.4 代码审查时重点看什么

审查同学重点检查：

- 坐标系和单位是否正确。
- 矩阵维度是否正确。
- 输入输出是否清楚。
- 是否影响已有脚本。
- 是否有硬编码路径。
- 是否有重复代码或明显不可维护的写法。
- 是否需要补充测试或 demo。

### 8.5 遇到冲突先沟通

如果两个同学正在改同一个模块，先在群里说明：

```text
我现在在改 src/filters/ekfUpdate.m，预计今天晚上提交 PR。
```

这样可以减少冲突。

## 9. 建议的新成员第一次练习

每位新成员可以先做一个低风险练习，熟悉完整流程。

练习任务：

2. 新建分支：`docs/你的名字-onboarding-test`
3. 在 `docs/` 下新增一个个人练习文件，例如 `你的名字-git-practice.md`
4. 写三行内容：

```markdown
# Git 协作练习

姓名：
我已经成功克隆仓库并创建分支。
```

5. commit。
6. push。
7. 发起 Pull Request。
8. 请另一位成员 review。
9. 合并后删除练习分支。

完成这个练习后，再开始改 MATLAB 核心代码。
